# LÉLU on iPhone — Capability Report (no Mac required)

Device target: **iPhone 16 · A18 · iOS 26.5.2** · browser-based development via Freebuff + GitHub.
Every capability below is classified honestly for what iOS actually permits a **web app** to do.
Nothing is faked: LÉLU reports a capability as available only when the underlying mechanism
really exists on the device, and the Device panel shows the live, detected status.

## Classification key

| Class | Meaning |
|---|---|
| **1. WORKING NOW** | Works in this web app on iOS today |
| **2. IMPLEMENTABLE** | Can be built into the existing web app (implemented where possible) |
| **3. REMOTE** | Requires a remote/cloud component to function end-to-end |
| **4. NATIVE** | Requires Apple native tooling (Xcode/macOS — out of scope per constraint) |
| **5. NOT AVAILABLE** | iOS does not expose this to any web app |

## What was implemented in this pass (all additive — existing systems untouched)

- **`src/core/native/`** — `NativeCapability` contract + singleton `NativeCapabilityRegistry`
  (register / snapshot / invoke / subscribe) and 21 real adapters.
- **`ToolResolver`** in the existing `AIRouter` chain + `RouterContext.native` —
  LÉLU's cognition can inspect and invoke device capabilities through the same router the
  provider fallback chain uses.
- **`AIService.runCapability()` / `nativeCapabilities()`** — read-only snapshots + gated execution.
- **PWA shell** — manifest, apple-touch icons (generated by `scripts/generate-icons.mjs`),
  service worker (offline shell + push + notification click), iOS meta tags, production-only SW
  registration.
- **`GenesisDevicePanel`** (Device dock tab + ⌘K command) — live, honest capability status.
- **`DeepLinkIntake`** — `?ask=…` prompts flow into the existing chat/cognition pipeline.
- **GitHub Pages workflow** (`.github/workflows/deploy-pages.yml`) — cloud build + host,
  no Mac required.

## What needs a remote component (class 3, next step)

**Web Push notifications** are the highest-value class-3 item. To finish them:
1. A small push backend (e.g. a Convex action or a tiny serverless function) holding
   subscriptions and sending pushes via VAPID (web-push).
2. User provides the VAPID public key → stored through the project's keys UI; the web app
   calls `push.subscribe` only while the app is **installed to the Home Screen**.
3. After subscribing, the installed LÉLU can show notifications when closed — the service
   worker handler is already in place.

## Explicitly NOT done (per constraints)

- No native iOS project (requires macOS/Xcode — out of scope). The `native.bridge` capability
  is the exact seam a future native companion registers through.
- No fake capabilities: haptics, App Intents, URL schemes, and true background execution are
  reported as the platform limits they are.
- Cognition, memory, providers, voice, Genesis, workspace/visual engines, `.env` and existing
  API fallbacks were **not** modified.
