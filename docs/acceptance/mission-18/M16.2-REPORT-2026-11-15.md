## 1. What was built

The creative engine already owned geometry, components, materials, lifecycle and persistence. Nothing in that engine was rebuilt. What was missing was a presentation adapter inside the running scene, plus a way to drive it without a console.

| File | Role |
| --- | --- |
| `src/core/couture/sceneTransform.ts` (new) | The only conversion between creative space (millimetres, z-up) and scene space (metres, y-up). Rotation is converted as a quaternion through a basis change (`B · Rz·Ry·Rx · B⁻¹`, `B = Rx(−90°)`), not by swapping Euler angles. |
| `src/app/scene/genesis/cosmos/CreativeObjects3D.tsx` (new) | The R3F layer: subscribes to the canonical store, builds one `BufferGeometry` per part from `meshToScene`, assigns the part's textile/metal/stone material, applies the object transform, draws selection highlight, raycasts in the capture phase, drags move/rotate/scale with a commit through `store.setTransform`. Disposes geometry on revision change and unmount. |
| `src/app/scene/genesis/cosmos/creativeGesture.ts` (new) | Gesture mutex (`beginCreativeGesture`/`isCreativeGesture`), selection state, tool mode (`select`/`move`/`rotate`/`scale`), plus `creativePlacementInFront()` so a new creation lands where the camera is looking. |
| `src/app/scene/genesis/cosmos/creativeProbe.ts` (new) | Read-only frame statistics written to `window.__leluCreativeFrames`; never writes to the store. |
| `src/app/scene/genesis/cosmos/CreativeObjectsDock.tsx` (new) | In-world control dock (HTML): build gown / pendant / chair, Select/Move/Rotate/Scale, Focus, Detach, Reattach, Float, Take out, Restore, Undo. 40 px minimum targets, no hover-only controls. Calls the same store and bridge the tools call. |
| `src/core/cosmos/CreativeObjectBridge.ts` | Placement now converts creative millimetres to Cosmos metres once, so `SpatialObjects` no longer receives millimetre coordinates as if they were metres. |
| `src/core/couture/objects.ts` | Added `subscribe()`/`notify()` so the renderer listens to the store instead of polling. Store remains the only authority. |
| `src/app/scene/genesis/GenesisV2Scene3D.tsx`, `render/GenesisRenderer.tsx` | Mounted `<CreativeObjects3D />` next to `<SpatialLayer />` in both canvases (v2 inside the root; v1 as a sibling of the slowly rotating `GenesisWorld` so a creation does not orbit the Core). |
| `src/app/scene/genesis/GenesisV2CameraRig.tsx` | `pointerdown`/`pointermove` return early while `isCreativeGesture()`, so a finger on an object never orbits the camera. |
| `src/app/scene/genesis/GenesisInterface.tsx` | Mounts the dock above the scene (not inside the canvas: an R3F portal of DOM children crashes the reconciler — see limitations). |
| `tests/couture-scene-transform.test.ts` (new) | 8 tests pinning the coordinate and rotation conversion. |

No new dependency, no second registry/scene/persistence layer/dispatcher.

## 5. Known limitations and open defects (read before continuing)

1. **Mesh visibility not confirmed visually.** Objects are in the scene with correct transforms and `visible: true`, and the geometry is valid, but no screenshot shows them. The most likely causes, in order: (a) the objects are small at the default camera (a 26 mm pendant is ~11 px at 2.2 m); (b) the two earliest objects sit at scene radius ≈ 1.99 m, i.e. exactly on the Core/planet surface (`TestPlanet` r = 2.0), so they are embedded in the planet; (c) the dock covers the screen region where an object placed in front of the camera projects.
2. **Dock buttons stopped responding in the last tab.** With the dock portalled to `document.body` (needed because the Cosmos HUD and the home cards each sit in their own stacking context and paint over an in-interface panel), `element.click()` and coordinate clicks both produced no state change, while the same dock did build a pendant in an earlier tab. React 19 event delegation to an out-of-root portal container is the prime suspect. Until this is resolved the dock cannot be relied on as the manipulation surface.
3. **R3F portal crash (fixed, recorded so it is not repeated).** Rendering the dock with `createPortal` from inside the R3F tree throws `R3F: Span is not part of the THREE namespace`. DOM overlay content must be mounted outside the canvas.
4. **Preview environment instability.** The Cloud browser tab became unresponsive three times (reload blank with `#root` empty, then `Page.captureScreenshot: Internal error`), reproducibly after a heavy local build (chair) or after editing files while the tab was live (Vite dep re-optimisation). The same build served fine in a fresh tab. This blocked the screenshots, not the code.
5. **No iPhone.** M16.2-O04 stays BLOCKED.
6. **No measurements.** Nothing in this report is a performance measurement; the frame probe exists (`window.__leluCreativeFrames`) but the loop in the paused tab only counted the mount frame, so its numbers are meaningless and are not quoted.
