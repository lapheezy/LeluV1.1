## 2. What happened to the target branch

**Verdict: independent reconstruction.** It is not a rebase of this work, not a
reset, and not a force-push over it.

The evidence is the commit graph, not a narrative:

1. Both branches descend from the *same* merge base, `a4f5df3` — the Mission 15
   record. Everything after it is separate work.
2. The target's four commits are a second, parallel implementation of the same
   capability: `8101ec2` "Give a constructed thing a life of its own in the
   Cosmos", `1cfd498` "Open the Cosmos…", `4ea29fc` "Make the Cosmos objects
   visible, touchable and redrawn", `d8fb056` "Put objects where they can be
   seen…".
3. The feature's twelve commits are the WP01–WP04 line: the couture engine
   (`c6f8640`), the object model (`27e12f7`, `fb7fa94`, `e23978b`), geometry
   selection and focus (`90c98ac`), autonomous interaction (`95bd992`),
   continuity and verification (`7269db5` … `9c70cbe`).
4. Reacting to the target being four commits ahead *after* the feature branch
   was pushed is consistent with a sibling workstream landing its own creative
   line in the meantime, not with this branch being rewritten: no commit of ours
   changed SHA, and the feature's remote tip still equals its local tip.

## 3. The "deletes selection.ts / textiles.ts / sculptural.ts" report

That claim came from a diff taken between the **feature** tree and the target
tree, which is not a statement about either branch's history:

```text
$ git ls-tree -r --name-only origin/integration/… -- src/core/couture
(empty)
$ git diff --stat 2068472 d8fb056 -- src/core/couture
 src/core/couture/selection.ts  | 65 --------------------
 src/core/couture/textiles.ts   | 606 --------------------
 src/core/couture/sculptural.ts | 355 --------------------
```

`src/core/couture/` is **added by the feature lineage**; the target simply never
had it. Nothing was deleted by the target, and restoring those files there would
create a second object model beside the one the target uses.

**Two coherent architectures, one capability.** Merging the trees would ship two
object stores, two tool families and two compilers — the opposite of "one
coherent creative execution path". So the reconciliation keeps the target's
architecture (it is the branch the workforce consolidation is built on) and
ports the WP04 *capability* onto it.

## 5. Merge strategy chosen, and why

| Option | Verdict |
|---|---|
| Normal merge of the two histories | **Rejected** — preserves both trees, leaves two competing creative engines and duplicate tools |
| Cherry-pick the WP04 commits onto the target | **Rejected** — the commits reference `src/core/couture/*`, which the target does not have; every pick conflicts on files that should not exist there |
| Reconciliation branch from the target, capability ported | **Chosen** |
| Restore `src/core/couture/*` on the target | **Rejected** — recreates a parallel object model the branch deliberately does not use |

Reconciliation branch: `integration/m16-3-wp05-reconciliation`, parent
`d8fb056` (the target tip at the time of this report), created as a normal
branch — no reset, no force, no history rewrite. Both original branches and all
their commits are untouched.
