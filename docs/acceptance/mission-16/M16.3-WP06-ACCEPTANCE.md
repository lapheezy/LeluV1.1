# M16.3-WP06 — Live Chat-to-Cosmos Execution Path: Repair and Acceptance

| | |
|---|---|
| Branch | `integration/m16-3-wp05-reconciliation` |
| Base commit | `52bddb54759100a183196b6e36ca3485e34b1079` |
| Evidence | `artifacts/m16-3/wp06/` |
| Harnesses | `scripts/wp06-probe.mjs`, `scripts/wp06-live.mjs`, `scripts/wp06-geometry.mjs` |

WP05 ported conversation-scoped referents, operation verification, bounded retry and
honest failure text onto the target's Cosmos object architecture. Its browser
acceptance was blocked: the chat surface showed placeholder bubbles and the object
store never received an object. WP06 was asked to find the real cause and prove the
live path.

Two separate things were wrong, and only one of them was in the application.

---

## 1. Root cause of the "skeleton chat"

**The chat was rendering.** In the WP05 session the sentence submitted to the
composer was not the sentence that was compiled: the composer held one character,
so the app routed `"b"` — a request with no deterministic plan — towards the model
providers, which were rate-limited, and the pending turn was photographed before it
settled.

Evidence, in the order it was gathered:

1. `artifacts/m16-3/wp06/probe-report.json` — with the full sentence inserted, the
   same surface renders a real answer in 0.7 s:
   `Built by my construction engine … ✓ build (creative.build) … kind chair …`,
   with `no object ever spawned` replaced by real tool output.
2. A per-keystroke instrumentation run showed `keydown` and `keypress` firing for
   every character while `beforeinput` fired **only for the first one**, and the
   textarea stayed editable (`readOnly:false`, `disabled:false`, focused,
   `selectionStart:1`).
3. Control experiment: a plain `<textarea>` injected into the same page — and a
   `<textarea>` on a **blank page** in the same browser — behaves identically
   (`"hello world"` → `"h"`).

Conclusion: this VM's headless Chromium accepts exactly one character of synthetic
per-key text in any text field. The composer is a normal controlled textarea
(`value={input}` + `setInput(event.target.value)`, `GenesisChat.tsx`); nothing in
the app drops keystrokes. The WP05 "skeleton" was a **harness artifact plus a
pending turn**, not a chat-rendering defect. The harness now inserts the sentence
as one `input` event (the event a human keystroke produces for React) and presses
real Enter.

What the app does while a turn is pending — placeholder rows in the transcript
before the reply lands — is unchanged and is not a permanent state: every one of
the 15 live turns settled, median 693 ms, no turn left a stop control behind.

## 2. Provider 429 — classified separately

`probe-report.json` captured the failing response in full:

```
POST /api/model/openrouter/chat/completions → 429
{"error":{"message":"Rate limit exceeded: free-models-per-day. Add 10 credits to
 unlock 1000 free model requests per day", "code":429,
 "metadata":{"headers":{"X-RateLimit-Limit":"50","X-RateLimit-Remaining":"0"}}}}
```

* It is **daily free-tier quota exhaustion** for the OpenRouter account, not a
  transient rate limit and not a cooldown of this app's own retry logic.
* Groq and GitHub Models were attempted after it in the same fallback chain
  (`/api/model/groq/...`, `/api/model/githubModels/...`) and did not answer either.
  No provider was invented or bypassed, and no paid service or credential was added.
* Those requests come from the app's **startup background work**, not from the
  chat turn: with a `window.fetch` spy installed over three consecutive
  deterministic turns, the turns themselves made **zero** calls to `/api/model/*`
  (only `/api/voice/status` and `/api/execution/events` appeared). Chat latency
  (243–1437 ms) is entirely local. In one later acceptance run a single background
  provider request landed inside a turn's window (`modelRequestsDuringTurns: 1`);
  that is the startup chain, not the command, and its failure changed nothing in
  the turn's execution.
* Because the deterministic route does not consult providers, the interface stays
  usable without a model: 15/15 live turns executed, `modelRequestsDuringTurns: 0`.
  When a sentence has no deterministic plan the app says so honestly instead of
  pretending: `"I'm in offline mode right now — all AI providers are unreachable or
  unconfigured…"` (captured in `probe-report.json`).

## 3. The live defect WP06 actually found and fixed

WP06-P04.9 asks that a pronoun-only command in another conversation must refuse
rather than inherit a selection. Live, it did inherit it: in a freshly created
conversation, `rotate it 90 degrees` rotated the object another conversation had
selected (store went `[0,0,0] → [0,90,0]` while the transcript belonged to a new
chat).

Cause: `resolveCosmosReferent()` fell back to `store.selectedId()`, and the store's
selection is one value for the whole Cosmos. The conversation-scoped memory
(`rememberCosmosReferent`) was correct but empty in the new conversation, so the
global selection answered a pronoun it did not own.

Fix, in the WP05 capability module rather than a second registry:

* `continuity.ts` — `rememberCosmosSelection(conversationId, objectId)` records
  which conversation put an object into the visible selection, and
  `selectionBelongsTo()` only lets that selection stand in for a pronoun in the
  conversation that made it. A selection made outside any chat (a click in the
  scene) stays world-level and usable everywhere.
* `CosmosObjectTools.ts` — the shared `judged()` path records the selection owner
  after every successful operation, next to the referent it already recorded.

Two further honesty fixes made while proving the path:

* A rotation was reported as `Moved: obj_1 …`. The frame tool now names the change
  it made — `Turned` / `Resized` / `Moved` (and combinations) — via `whatChanged()`.

## 5. Visual geometry (WP06-P05) — PARTIAL, not a PASS

Frames and data: `artifacts/m16-3/wp06/geometry/` (4 frames + `geometry-report.json`).

Each transform was issued through the chat, then the frame was captured with the
object's stored frame recorded beside it:

| Frame | Position | Rotation | Scale |
|---|---|---|---|
| `01-initial.png` | [3.2, 0.9, 7.2] | [0, 0, 0] | 4 |
| `02-rotated-90.png` | [3.2, 0.9, 7.2] | [0, 90, 0] | 4 |
| `03-doubled.png` | [3.2, 0.9, 7.2] | [0, 90, 0] | 8 |
| `04-moved-left.png` | [2, 0.9, 7.2] | [0, 90, 0] | 8 |

Pixel change between frames: 64.97 %, 55.69 %, 56.08 %.

**Those numbers cannot be attributed to the object.** In this headless VM the world
canvas renders as an unframed field (noise/particle background) and the chat
surface cannot be dismissed — `Close Chat Universe`, `Minimize` and
`Close window` clicks leave it on screen, and the render budget is held occluded
while the Universe is open. The frames therefore show the *application*, not a
measurable silhouette of the placed object. The only legible 3D image in the
frames is the Creation Studio artifact preview, which renders the build, not the
object's live frame.

What is established, and how:

* the frame changes are **verified by the app's own verification layer** (target,
  expected value, preserved components, persisted copy) and by the independent
  store read above — rotation, scale and position each landed exactly where asked,
  and each preserved the components it did not touch;
* no claim is made that a human can see the 90° turn, the doubled size or the
  moved position in the captured pixels.

Visual geometry stays **BLOCKED** for the same reason WP05 reported, now with a
precise cause (unoccluded world render unavailable in headless SwiftShader), rather
than being reported as passing.

## 8. Remaining limitations

1. **Visual geometry is not visually proven** — see §5.
2. **No model-driven comprehension.** OpenRouter's free daily quota is exhausted
   (`X-RateLimit-Remaining: 0`); Groq and GitHub Models did not answer. Sentences
   without a deterministic plan fall back to the app's honest offline reply. No
   provider, credential or paid service was added.
3. **Multi-step dependent-skip is not exercised live.** The deterministic compiler
   emits one step for the Cosmos sentences tried (`select the lamp and rotate it 90
   degrees` compiles to a single select of the whole clause), so the live path can
   only show the follow-up behaviour (check 17). The `↷ … not attempted` skip in
   `DirectResolver` is covered by unit tests and the WP05 dispatch harness, not by a
   browser turn.
4. **`rotate it by banana degrees` compiles to `cosmos.object.animate`** ("spins at
   0.08 on y") instead of being rejected. That is a compiler leniency outside
   WP06's scope; the invalid-operation check therefore uses a name the Cosmos does
   not contain, which the tools refuse honestly.
5. **Typing has to be inserted, not typed,** in this VM's Chromium (one character
   per field, proven on a blank page). A human user is not affected; the harness
   documents the substitution.
6. The chat surface keeps its pending placeholder rows until a turn settles; with
   providers unavailable and no deterministic plan, the honest offline reply is
   what resolves the turn.
