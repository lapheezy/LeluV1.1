## 2. Existing architecture audit

One registry (`ToolRegistry`), one dispatcher (`ToolDispatcher.dispatchToolCall`
→ `AutonomyGate` → executor), one creative store (`CreativeObjects`), one bridge
(`CreativeObjectBridge`), one camera bus (`__cosmosCamera` /
`dispatchV2CameraCommand`), one renderer.

Creative operations already existed as **one** tool — `couture.objects` — with
23 lifecycle actions executed deterministically, plus `couture.design` for
building. WP03 added to that tool; it did not create a parallel engine.

The one structural change: selection and the focus request lived in
`src/app/scene/genesis/cosmos/creativeGesture.ts`, which core cannot import.
They were **moved** to `src/core/couture/selection.ts`, and `creativeGesture`
re-exports them unchanged, so the dock and the scene keep their API and there is
still exactly one selection authority.

## 4. Object identity and resolution

Identity is the store's canonical id (`obj-product-1`, `obj-jewelry-2`,
`obj-garment-3`), the same id the Cosmos bridge mirrors (the *spatial* id in the
dock's notice is a different id space and is not used for resolution).

`resolve()` refuses ambiguity with the candidate list rather than guessing; the
tool surfaces that refusal verbatim. Verified: with two chairs,
`move the chair` returned `"chair" matches 2 objects: …` and nothing moved
(DISPATCH).

## 5. Cognition-to-tool traces

Two routes now reach the same `couture.objects` calls:

* **model route** — unchanged: model emits a tool_use, dispatcher runs it.
* **deterministic route (new)** — `compileCreativeObjectPlan()` turns a sentence
  into a `DirectPlan`, which the existing `DirectResolver` already executes
  through `dispatchToolCall`. No model, no cost, same gate and events. It is
  wired into `compileDirect` *before* the build/create rules so that
  "make the pendant twice as large" transforms the object instead of building a
  new one.

Guard against hijacking: a clause only compiles when it names a creation noun or
uses a pronoun with a real referent. (`what is the weather in Lisbon` compiles to
nothing — TEST.)

## 6. Authorization evidence

Every call went through `dispatchToolCall`, which runs `AutonomyGate` and the
existing risk policy (risk level 1, `READ`/`WRITE`). No executor writes the store
outside the store API and no test bypasses the dispatcher for the DISPATCH
evidence. Unauthorized-operation scenario (F) was **not** exercised as a denied
risk-level-4 action; the tool has no destructive action exposed
(`deletePermanently` is not a tool action), so there is nothing to deny —
recorded as NOT TESTED rather than as passed.

## 7. Verification evidence

Every mutating action now returns `data.verification`:
`{ action, objectId, before, after, storeChanged, persisted, … }`, where
`before` is a plain snapshot captured *before* the call (store operations mutate
in place, so a reference would compare equal to itself). Verified in the
DISPATCH run:

* `select` → `storeChanged: false`, revision unchanged (selection is a pointer);
* `rotate 90°` → `storeChanged: true`, `persisted: true`, rotation `[0,0,90]`,
  position unchanged;
* `scale ×2` → scale `[2,2,2]`, same object id.

Geometry verification is **separate**: the store can be right while nothing is
drawn. The scene publishes `window.__leluCreativeDebug.transforms` (added here)
so evidence can compare what is drawn with what is held. Visual verification is
only claimed where a screenshot exists.

## 9. LIVE evidence and the one gap it exposed

`scripts/verify-creative-live.mjs` types into LÉLU's own composer in the running
app (`?perf-world`, guest mode) and reads the scene's canonical transforms.

* `select the chair` → selection became `obj-product-1`. **LIVE + VISUAL**
  (`artifacts/m16-3/wp03/live-01-selected.png`). This is the end-to-end path:
  sentence → compile → dispatch → tool → store → scene.
* `rotate it 90 degrees` and `make it twice as large` → **no change**
  (`live-02`/`live-03` screenshots, `live-report.json` shows rotation `[0,0,0]`,
  scale `[1,1,1]`).

Root cause, isolated in Node: the compiler resolves "it" from the *current
selection read at compile time*. With a referent it emits the correct call
(`rotate it 90 degrees` → `{action:"rotate", rotation:[0,0,90]}`); with
`selectedId: null` it correctly emits **nothing** rather than guessing. In the
live run the referent was not visible to the compiler at that moment, so those
two turns compiled to no plan and were answered by another route. The fix is
narrow and named: carry the last tool result's object id into the next turn's
compiler context (and/or read the selection inside the resolver rather than at
plan time). It is **not** applied in this work package, so the relay is reported
PARTIAL, not PASS.

## 10. Ambiguity handling

Store-level refusal with candidates (TEST + DISPATCH). The deterministic
compiler never invents an id: unresolved instructions produce no plan, or a call
that the tool rejects with the specific missing argument (e.g. "move needs
position, delta, or relativeTo").

## 11. Persistence and reload

DISPATCH: after build → place → select → rotate → scale → relative move, the
script calls `store.reload()` (the same path a page load takes, over a real
`localStorage` shim) and asserts positions, rotation, scale, object count and
ids are unchanged. All assertions passed. The gown reload gap from WP02 (which
was cut off by a harness timeout, not by a defect) is **closed at DISPATCH
level**; it is not re-proven in the browser.

## 12. Human and autonomous coexistence

WP02's harness still applies: a person's click selects geometry, a drag moves the
object, an empty drag orbits only the camera, and a dock press changes nothing.
Autonomous selection writes the same channel the human path writes, so a
selection made by a tool is the same selection the dock shows and the scene
highlights; no lock, bus or second dispatcher was added. No regression observed
in the 51-test focused run or the live select.

## 15. Performance

**NOT MEASURED.** No latency figures are claimed for identification,
capability discovery, authorization, dispatch, geometry update, verification or
persistence. What can be said without a measurement: the deterministic compiler

## 16. Remaining limitations

1. **Level 3 is PARTIAL.** Deterministic instruction → tool → store → scene is
   proven for selection (LIVE) and for every operation (DISPATCH); the live
   two-turn relay fails on pronoun resolution (§9). Model-driven comprehension is
   **BLOCKED**: `scripts/verify-agentic.ts` reports all 9 providers
   `missing-credentials-or-provider-cooldown` and the app console shows
   429/502/503 `BROKER_CONTRACT_VIOLATION`.
2. **Level 4 is NOT ACHIEVED.** Self-evaluation, failure detection and
   self-correction were not demonstrated; the verification payload is evidence
   for a human or a model to read, not an autonomous correction loop.
3. Visual verification is browser-only and depends on the dev probe.
4. Unauthorized-operation denial (scenario F) is untested because no destructive
   creation action is exposed.
5. Section-15 performance numbers are absent by choice, not by accident.
6. The render-manager source-text test asserts code shape; it was updated to the
   current gate rather than deleted, but it remains a weak form of evidence.
