## 4. Referent continuity (WP04)

`src/core/cosmos/objects/continuity.ts`:

* resolution order — newest valid `obj_*` id in **this conversation's messages** →
  the id this conversation's last successful tool result touched → the visible
  selection;
* every candidate is validated against the store on read, so a removed object
  (it moves to the trash, where `get` cannot see it) is dropped;
* the per-conversation record is bounded (50 conversations, 2 h) and keyed by
  `conversationId`, so two chats cannot share it;
* **no newest-object fallback**: `store.resolve("")` still returns the newest
  object for its other callers, but the tools no longer call it with an empty
  reference — they call `resolveCosmosTarget`, which refuses with the object list;
* a name matching several objects is refused with their names.

No singleton and no second store was introduced.

## 6. Verification and bounded correction (WP06)

`verifyObjectOperation` checks target, change, requested value, untouched fields
and persistence; critical failures are **FAILED**, secondary ones **PARTIAL**,
and a FAILED verdict makes the tool result `ok:false` with the reason. A
transform that never reached the store is re-applied **once**; a second failure
is reported, never looped. Dependent compound steps are skipped and named.

| Case | Result | Evidence |
|---|---|---|
| Retry success (one dropped write) | VERIFIED, `correction.tries = 2` | TEST + DISPATCH |
| Retry exhaustion (permanent fault) | `ok:false`, FAILED, exactly two attempts | TEST + DISPATCH |
| Incorrect target | FAILED | TEST |
| Incorrect requested value | FAILED | TEST |
| Partial mutation (untouched field moved) | PARTIAL | TEST |
| Persistence failure | never VERIFIED | TEST |
| Dependent step after a failure | skipped, named | TEST + DISPATCH |
| Independent step after a failure | still runs | TEST + DISPATCH |
| No duplicate side effects | the retry only fires when nothing changed | TEST (`attempts === 2`) |

real composer. It reaches the chat, sends the turns, and then cannot read a

## 12. Remaining limitations

1. **Live chat on this branch is unusable in this environment.** The composer
   accepts text, but replies never render (skeleton placeholders) and providers
   rate-limit. Any live claim about this branch must wait for that surface.
2. **Visual geometry is unverified.** The store says a rotation exists; no frame
   shows it.
3. **WP02/WP03 suites are not portable** to this branch by construction. Their
   capability is provided by the target's own modules, whose tests pass; the
   feature branch's suites remain valid on that branch.
4. **The integration branch was not fast-forwarded by me.** The reconciliation
   branch descends from it, so advancing it is a fast-forward a maintainer can
   take deliberately; doing it unilaterally would move a shared branch other
   workstreams read.
