## 2. Architecture found before implementation (Phase A)

There was **no Neural Map**:
- `src/core/graph/Graph.ys` is an empty file.
- `cognition/KnowledgeGraph` is an in-memory, unpersisted structure private to `CognitiveCore`, with free-string relations.
- Each Cosmos authority keeps its own relationships, persisted separately:

| Authority | Holds | Persistence | Change signal |
|---|---|---|---|
| `CosmosObjectStore` (M16) | 3D objects, parent/children, groups, trash, provenance (text) | KvStore `cosmos.objects.v1` | `subscribe` |
| `CosmosNavigation` (+ `CosmosLiveMap`) | core → galaxy → planet/room; refs to agents/projects/conversations | KvStore `cosmos.nav.v1` | `subscribe` |
| `SpatialObjects` | real records placed in rooms (pointers) | KvStore | `subscribe` |
| `SpatialSceneGraph` | LÉLU's Room authored objects + `connected/orbits/contains/aligned` + undo journal | in memory | `subscribe` |
| `ToolRegistry` / `ToolDispatcher` | capabilities | — | `subscribe` |
| `InterfaceCatalog` / `InterfaceCompositionStore` (M17) | interfaces, compositions | KvStore | `subscribe` |
| `CosmosEntityRegistry` | UI-event telemetry entities | in memory only | — |

**Decision.** The Neural Map is an **index over these authorities**, not a store:
- canonical ids derived from each authority's own ids;
- one typed relation vocabulary;
- no persistence of its own (a reload re-derives it from the authorities' own persisted state);
- no writes (operations run the existing tools).

This adds no graph database, no second object store, no memory system and no dispatcher.

## 4. Contract and relationship types

`src/core/neural/NeuralMapTypes.ts`:
- `NeuralEntity` carries `id`, `type`, `label`, `authority`, `sourceId`, `state`, `spatial`, `provenance[]` (with `ref`), `operations[]`, `facts` and `updatedAt`.
- `NeuralRelation` carries `from`, `type`, `to` and the `authority` that states it.

Relation types:
- `contains`, `part-of`, `attached-to`, `located-in`, `member-of`;
- `derived-from`, `extracted-from`, `created-from`;
- `references`, `operated-by`, `presents`;
- `connected-to`, `orbits`, `aligned-with`.

The Room's own kinds map 1:1 onto the last three plus `contains`.

**Spatial versus semantic.** `spatial` (position, rotation, scale, `space`) is separate from relations. Closeness never creates a relation; a move changes only `spatial` (TEST + DISPATCH).

**The one change to an existing authority.** `CosmosObjectStore` provenance entries gain an optional structured `ref` (duplicate, integrate, extract, remove), and remove/restore now record a provenance step.
- Relations come from that data, not from wording.
- Objects saved before M17.2 fall back to the store's own fixed phrasing (`from obj_…`, `out of obj_…`), tested.
- No orphans: a lineage relation is drawn only to an object the store still holds, live or in the trash.

## 13. Limitations, findings and blockers

- **F1 (pre-existing routing overlap).** In chat, "move the gear next to the cabin" is claimed by LÉLU's **World** tools (`world.state` / `world.object`), not `cosmos.object.position`. The move evidence therefore uses DISPATCH. Not fixed: it is a router decision between two spatial systems.
- **F2 (name resolution).** After duplicating, "the gear" resolves to the newest copy (`CosmosObjectStore.resolve` picks the latest match). The map was right; the evidence uses ids where names are ambiguous.
- **Undo/redo for Cosmos objects** does not exist in `CosmosObjectStore`, and was not invented.
- **"Clone/fork" of objects** is not an object-store operation; only duplicate exists.
- **No GPU here.** On this container's software renderer the Cosmos world deliberately does not paint (existing "light" profile). Shot 09 uses the app's dev-only `?perf-world` switch, which paints the real scene. The grain in that shot is the Cosmos's own "static" atmosphere phase.
- **Not yet hosts of the embedded contract:** Home, Chat Universe, the creative, engineering and System UIs. They join through `useNeuralEntity` + `NeuralView` + `runNeuralOperation` (`genesis/neural/useNeural.ts`) and the `NID` id scheme.
- **Standalone map, deferred:** other styles (3D, force-directed, whole-graph overviews) and multiple standalone presentations. One standalone view exists and is registered; the catalog, launch and composition contracts support more.
- **Not reported as success:** `MemoryOrchestrator.persist` "accepted" reporting (M17.1 note) and the Original LÉLU Supabase history gap (M17.1) are unchanged.
- **Mobile:** not verified on a physical iPhone in Safari.

## Architecture

- **One index.** Every card reads `neuralMap()`, the same index the standalone map and the Cosmos inspector read.
- **New adapters, pure, over existing authorities** (`core/neural/adapters.ts`):
  - `conversationsPartition` reads MultiChatStore.
  - `artifactsPartition` reads StudioStore, which holds the Creative Kit's output.
  - `projectsPartition` reads ProjectStore.
  - `sandboxPartition` reads SandboxFS.
  - `homePartition` reads the Home's own catalog.
  - Chats, artifacts and projects keep the `record:<kind>:<id>` ids other authorities already pointed at. Their owner now claims the id, so a reference and the thing itself are one entity.
- **Relationships are only those the source records state:**
  - a merged chat lists where each message came from → created-from;
  - a chat's links → connected-to;
  - a chat's project → part-of;
  - an artifact's conversation → created-from;
  - a file's folder → part-of;
  - the Home lists its apps and destinations → presents;
  - an app's tools → operated-by.
- **Live:** `connectNeuralMap` subscribes to each store's own notifications. The new stores are imported on demand, so the entry chunk does not grow. Chats re-derive only when what the map shows changes, never per streamed token.
- **SandboxFS** gained a `subscribe()`; it previously had no change notifications.
- **No-op updates are skipped:** a store that notifies without changing anything the map holds no longer bumps the version or wakes any view (`noopCount()`).
- **The card:** `NeuralEmbed` (lazy chunk) + `NeuralEmbedSlot`/`NeuralToggle`.
  - Each interface places the card in its own layout.
  - Following a relationship stays inside the card, and ← walks back.
  - "Open map" opens the standalone map over the interface on the same id (`layer: "over"`, z 640); Return lands back in that interface.
  - Nothing mounts or subscribes until the card is opened, and closing it releases everything.
- **Nothing new of the kinds the prompt forbids:** no graph DB, store, memory, persistence, dispatcher, event bus or renderer. Every operation runs through `dispatchToolCall`; routine inspection makes 0 model calls.
