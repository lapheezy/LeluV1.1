### O01 — LÉLU inhabits her Room

**Cause.** In the Room, LÉLU *is* the body standing in it (`LeluV2Presence`, inside `GenesisV2Scene3D`). The overlay companion (`LeluCompanion`) steps aside and pauses while she's there. It decided this from `state.activeScene === "genesisv2"` alone, so a Room shown as a composition region drew **two** LÉLUs with two render loops.

**Fix.** `useComposedRoomPresented()` reads the existing composition store: is the Room the *current* region? The Room region is only live while current. The companion now treats that exactly like the standalone Room. Nothing was added to the avatar, cognition or render system. The existing "hidden ⇒ `paused`" rule stops the companion's loop.

**Verified in UI:**
- standalone Room: companion `presence=world`, hidden;
- composed Room: companion hidden, exactly 1 in-room body (`canvas[data-lelu-spatial]`);
- Cosmos / System / Core regions: companion back beside you, visible;
- returning to the Room: in it again, 1 body;
- framed with the Room's own "◉ LÉLU" camera control: her body is loaded (no "unavailable" notice) and its projected chest is on screen.

**Observation (pre-existing, unchanged):** in the Room's default camera framing her body stands behind the Genesis Vault orb. It is the same in the standalone Room; the "◉ LÉLU" control frames her.

### O02 — Worlds control

**Cause.** The Spatial rail (`SpatialNavigator`, z 200 at the document root) and the Home's nav bar (z 260, but inside the interface root's own stacking context) shared the bottom centre on desktop. The rail won the hit test. Phones had already lifted the rail; desktop never did.

**Fix.** The rail already measured the chat composer and lifted itself clear of it. It now treats the nav bar and the orb as obstacles too, using the same `composerLift` maths. It's measured, not hard-coded.

**Verified:**
- `click()` (which fails if any other element would receive the pointer) on Worlds at 1024×768, 1280×800, 1440×900 and 1920×1080;
- all six nav buttons are the hit-test target;
- the rail's own buttons stay reachable;
- iPhone EMU: all nav buttons are inside the viewport and are the hit target, and a tap on Worlds opens the sheet.

**Side effect:** on desktop the rail now sits just above the nav bar. At 1440×900 it overlaps the empty middle of the Home's bottom "LÉLU — Here with you" strip.

### O04 — Live chat tool execution

**Deterministic path (VERIFIED, UI).** New explicit commands are compiled by `DirectResolver.interfacePlan` and run through the real `dispatchToolCall`, with the same AutonomyGate and activity events as a model's tool call:

| Command | Tool |
|---|---|
| `/interfaces` | `interface.list` |
| `/open <interface>` | `interface.open` |
| `/open composition <id>` | `interface.open` |
| `/close composition` | `interface.open` (close) |
| `/compose a + b` | `interface.compose` (create + open) |

Typed into the Chat Universe composer, the results were:
- the reply came from provider `lelu-direct` with 0 model calls;
- the System UI visibly opened;
- a 3-interface composition was created and opened;
- `/open a toaster` was refused, listing the valid interfaces;
- an unknown composition id was refused.

The dispatcher's own activity records show `interface.list:done`, `interface.open:done`, `interface.open:failed` and `interface.compose:done`. Permissions: `interface.list` and `interface.open` are READ (risk 0); `interface.compose` is READ+WRITE (risk 1).

**Unavailable launcher.** The honest failure is covered by UNIT tests (tool fails with "not mounted"; compose with `open:true` says "saved but not opened"). In the browser the shell is always mounted, so this was not exercised there.

**Defects fixed:**
- **False success claim.** The direct-reply preface reused a past-tense summary, so a refused command read "Opened a toaster. Done on this device…". Interface summaries are now phrased as the request, and the preface says "could not be done; the reason is below" when a step fails.
- **Wrong trimming.** The reply trimmer (written for web pages) cut the interface list's header and appended "the page is open in the conversation above". Interface results are now shown whole.

**Model-mediated path: NOT VERIFIED.** No model provider is reachable here: only Vite runs, and `/api/providers/status` returns Vite's HTML page fallback, not the broker. No paid inference was used. Natural-language phrasing ("open her room") is deliberately left to the model.

### O05 — Shared runtime continuity

A probe was written before a tour of Original LÉLU → Room → Cosmos → System → Core → Chat Universe and read back after it:
- an identity token stamped on the `MultiChatStore`, `AIService`, `AgentStore` and `MemoryOrchestrator` singletons;
- a message appended to the active conversation;
- a durable memory written through the `MemoryOrchestrator`.

After the tour:
- **same instances** (all four still carry the token, so no second store or runtime was created);
- same active conversation, message kept;
- agent count 11 → 11;
- the memory was recalled by the `local` authority.

Note: the Brain writes *selectively*, so only durable facts (here, a stated preference) are stored. Separately, `MemoryOrchestrator.persist` reports a provider as "accepted" even when the Brain dropped a non-durable candidate. That reporting quirk is pre-existing and was not changed.

**PARTIAL — Original LÉLU conversation history.** OG chat *turns* call the shared `AIService` (`og/compat/chat.ts`). But OG's conversation *list and history* are read from Supabase (`og/lib/conversations.functions`, signed-in server functions), a separate, pre-existing persistence. It isn't configured here, so OG lists no conversations, while Genesis and the Chat Universe show theirs. Unifying the two would change a persistence authority, which this WP forbids. Left as a known gap.
