## 2. Neural Map deletion invalidation

The code search found no `NeuralMap` store, index, cache key or persistence table. The "Neural Map" is a visualization/derivation over existing data, not a canonical record.

Therefore:

- no index is invented;
- no deletion invalidation code is added for a store that does not exist;
- when a source record is deleted, the next derivation simply sees the remaining authorities;
- if a future mission introduces a cached derived index, invalidation must be part of that index's own contract, not a second continuity authority.

This is an explicit scope decision, not a claim that deletion invalidation was implemented.

## 3. Forge and SpatialSceneGraph

- `SpatialSceneGraph` commits are guarded, revisioned and undoable in memory, but it has no `KvStore` persistence.
- Forge placements are read/written through `/api/forge/*` and stored server-side in `cosmos/placements.json`.
- Neither is silently folded into `SpatialObjects`, which is the local-first placement authority for record links.

## 4. Known non-continuity writer

`src/og/lib/conversations.functions.ts` directly inserts/updates/deletes conversations and messages through a server Supabase client. It is a separate OG server surface, not the Genesis `ContinuityEngine` path. It is recorded here as a real residual concurrency gap:

- its updates do not compare `continuity_revision`;
- its deletes do not create a continuity tombstone;
- it can race a conditional continuity write.

Fixing it requires a separate server-side design decision (route it through continuity or deliberately keep OG as a non-local-first surface). It was not changed in M14.5 because it is outside the requested browser continuity path and has its own tests and semantics.

- The only new migration affects the four row authorities used by continuity.
