## 2. Performance

Deterministic Node run after the M14.5 adapter changes:

| Measurement | M14.5 | M14.4 |
|---|---:|---:|
| Local project read median (1,000) | 0.003 ms | 0.005 ms |
| Local project read p95 | 0.008 ms | 0.013 ms |
| Local project write median (40) | 0.379 ms | 0.541 ms |
| Local project write p95 | 0.778 ms | 1.063 ms |
| Outbox processing (40) | 3.587 ms | 2.596 ms |
| Conflict detection + push | 5.899 ms | 3.894 ms |

Local reads/writes did not regress. Outbox/conflict work is slower because M14.5 adds content-equality checks, revision-token handling and first-seen reconciliation; the absolute cost remains a few milliseconds for a 40-operation batch. These are deterministic microbenchmarks, not UI frame measurements or real network latency.

Production browser cold boot was 1,941 ms and reload 2,064 ms in the final offline harness. M14.4's final build measured 1,711/1,912 ms. The reload is 152 ms slower and boot 230 ms slower in this run; run-to-run browser variance is larger than the continuity change, and no performance target was invented. This is reported as a measured difference, not a proven regression cause.

## 5. Operational caveats

- The revision migration must be applied before real deployment; without it the adapter falls back to a timestamp condition with the original same-millisecond limit.
- A document-backed authority has one row revision for several records; rebasing is allowed only when the target record is unchanged from its base hash.
- A direct OG server write can bypass the conditional path; see WP07.
