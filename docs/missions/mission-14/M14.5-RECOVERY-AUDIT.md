## 2. Harness and environment, verified

| Claim | Result |
|---|---|
| Harness reads `.env.local` | **TRUE** — `ENV_FILES` in both harnesses |
| Standard `SUPABASE_*` aliases | **TRUE but partial** — URL and key only; `NEXT_PUBLIC_*` and `SUPABASE_ANON_KEY` are not accepted by the harnesses |
| No extra credential file required | **TRUE** — `.lelu-runtime/` is optional and absent |
| Credential validation | **Was incomplete** — presence was checked, key kind was not |

Two defects were found and repaired:

1. **Quoted values.** `.env.local` stores values quote-wrapped. Vite and
   `plugins/loadEnvFiles.ts` strip the quotes; the harnesses did not, so a
   correct key arrived as `"sb_publishable_…"` and would fail 401.
   `unquoteEnvValue()` now matches Vite in both harnesses.
2. **Secret keys were accepted.** The guard only checked presence. With a URL,
   a ref and opt-in, an `sb_secret_…`, `sbp_…` or `service_role` key would have
   been used — bypassing RLS and producing a meaningless "real cloud" pass. The
   guard now refuses such a key with `FAIL` before a client is created, and
   never echoes it.

The two-profile artifact also recorded `LELU_M145_PROJECT_REF` (possibly
undefined) rather than the resolved ref; it now records the resolved value.

## 3. What blocks the cloud run

Confirmed from `.env.local` and the process environment, by name and shape only:

```text
SUPABASE_URL / VITE_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_URL   absent
LELU_M145_SUPABASE_URL                                        absent
LELU_M145_PROJECT_REF                                         absent
LELU_M145_EMAIL                                               absent
LELU_M145_ALLOW_REAL                                          absent
SUPABASE_PUBLISHABLE_KEY                                      present, but a SECRET key
```

So the block is not "the key is missing" but **"the project URL is absent and
the only key supplied is an admin secret"**. The app already refuses to publish
that key to a browser (`isBrowserSafeSupabaseKey` in the runtime key bridge); the
harness now refuses it too. Using it would bypass RLS and prove nothing.

The guard accepts only the isolated `lelu-v11-test` project
(`ugshflwlyakipeduifkd`); the production project cannot pass by ref or by URL.
