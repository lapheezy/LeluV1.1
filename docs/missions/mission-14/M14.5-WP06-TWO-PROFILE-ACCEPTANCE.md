## 1. Harness

`scripts/verify-m145-two-profile.mjs`:

- launches two independent Chromium contexts (separate `localStorage`);
- signs each into the configured Supabase project through the app's real sign-in gate;
- confirms `SupabasePersistence.getStatus() === "connected"` in each;
- installs the production `SupabaseContinuityTransport` and `ContinuityEngine`;
- creates a project in A, waits for B to pull it;
- takes both offline, edits the same project in each;
- reconnects A, then B;
- requires a real conflict with both names;
- resolves `keep_cloud`, requires both profiles to converge;
- reloads A and requires the resolved project to survive.

It never copies a session token between contexts. If only one test account is supplied, it records that this validates same-account two-session behavior, not separate account ownership.
