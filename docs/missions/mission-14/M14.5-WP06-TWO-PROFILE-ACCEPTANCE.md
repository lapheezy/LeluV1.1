## 1. Harness

`scripts/verify-m145-two-profile.mjs`:

- launches Chromium (visible when `LELU_M145_HEADFUL=1`);
- opens profile A at the app and requests the normal email sign-in link;
- waits for the person to complete the inbox step in that browser;
- confirms `SupabasePersistence.getStatus() === "connected"`;
- creates profile B as a second independent context with its own `localStorage`, seeded once from A's real authenticated storage state;
- confirms B is connected independently;
- installs the production `SupabaseContinuityTransport` and `ContinuityEngine`;
- creates a project in A, waits for B to pull it;
- takes both offline, edits the same project in each;
- reconnects A, then B;
- requires a real conflict with both names;
- resolves `keep_cloud`, requires both profiles to converge;
- reloads A and requires the resolved project to survive.

Profile B is not a second email sign-in and not a second account. It is the same account in independent browser storage. Cross-account RLS isolation is **not tested** and is reported as such.

No password is collected. No session token is printed or written to the artifact.
