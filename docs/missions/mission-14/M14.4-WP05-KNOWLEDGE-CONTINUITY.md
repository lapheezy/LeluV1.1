# M14.4 — WP05 KnowledgeGraph and Neural Map Continuity

**Status:** KnowledgeGraph continuity **VERIFIED** for local operation, revisioned document reconciliation, live-instance application and idempotency. Neural Map is **EXPLICITLY SCOPED** as derived state; no standalone persistent Neural Map index exists to synchronize.  
**Baseline:** `mission-14.3/independent-runtime-acceptance` at `9363966`.

---

## 1. What the source actually showed

`KnowledgeGraph` persists to `lelu.cognition.knowledge.v1` through the canonical `KvStore`. Its envelope contains:

```text
version, provenance: "local", revision, updatedAt, nodes[], edges[]
```

`KnowledgeLibrary` persists a different shape to `lelu.knowledge.v1` and is the only writer of `public.knowledge_items`.

No consumer, migration or writer treats the two stores as the same records. The names are related, the schemas and identities are not. M14.4 therefore **does not merge KnowledgeGraph into knowledge_items**. Forcing that mapping would have invented semantics and risked replacing a cognition graph with a library entry, or vice versa.

---

## 2. The chosen cloud representation

The graph is synchronized as an opaque per-user document in the **existing** `user_preferences` table:

```text
preference_key: lelu_sync_knowledge_graph
value: { format: "lelu.continuity.doc.v1", updatedAt, records: [graph envelope] }
```

Why this is safe:

- it uses an existing table, not a new graph database;
- the complete envelope travels together, so nodes and edges cannot be split across writes;
- the row has a conditional `updated_at`, so a stale device cannot overwrite a newer graph;
- the local envelope remains the canonical shape, and its own `revision` is preserved;
- applying the same envelope repeatedly is idempotent by node id and edge key.

The cloud copy is an optional mirror. It is never read as a second live graph by cognition; it is applied back into the local authority.

---

## 3. Local-first behaviour

- `addNode` and `connect` write the envelope locally and emit a local continuity signal.
- The graph continues to work with Supabase disabled; no cloud object is constructed on the boot path.
- A local write failure is still contained exactly as before: the in-memory graph remains authoritative for the session and the storage failure is not reported as success.
- The engine records the changed envelope as a pending operation. It does not block cognition on the upload.

---

## 4. Reconciliation

`KnowledgeGraph.applyPersistedEnvelope(envelope)`:

1. writes the normalized envelope back through `KvStore`;
2. updates every live `KnowledgeGraph` instance through `hydrateEnvelope`;
3. emits a **remote** continuity signal so the engine records the acknowledged base without creating a local pending revision.

`hydrateEnvelope` clears and rebuilds the node/edge maps by stable identity. Reapplying the same envelope therefore yields the same node count and edge count, not duplicates. The deterministic test applies the same envelope twice and asserts `nodes = 1`, `edges = 1`.

`ContinuityEngine` treats the entire graph as one record (`id: "graph"`). A graph conflict is a whole-envelope conflict; no automatic graph merge is attempted because node/edge field-level authority is not established.

---

## 5. Neural Map

**Finding:** no standalone persistent Neural Map store or canonical index exists in the inspected source. The map is a derived visualisation over the canonical cognition, knowledge, project and Cosmos authorities. There is no key, record id or writer that could become a second synchronized database.

**Decision:** Neural Map remains derived. It is rebuilt from the reconciled authorities and is not uploaded as a canonical record. No new index was created merely to satisfy the mission vocabulary.

**Limitation:** because the map is derived in the UI, M14.4 does not add a persistent index invalidation queue. If a component caches a derived map in memory, it must refresh from its source authorities after reconciliation; that refresh is outside the synchronization engine and is not claimed as verified UI behaviour.
