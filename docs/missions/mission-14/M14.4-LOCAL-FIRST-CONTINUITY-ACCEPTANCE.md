## 1. Executive result

LÉLU now has a real continuity layer rather than a blind cloud mirror.

- Local writes remain immediate and canonical. Continuity observes them after the authority has already persisted and notified.
- A durable sidecar revision ledger and outbox live in the existing `KvStore` (`lelu.continuity.sync.v1`), not in a new database.
- Projects, conversations/messages, the knowledge library, the cognition KnowledgeGraph, Cosmos spatial objects and Cosmos rooms are covered by the continuity contract.
- Cloud writes are conditional on the exact `updated_at`/document revision the client observed. A mismatch becomes a visible conflict, not an overwrite.
- A stale acknowledgement cannot mark a newer local revision synchronized.
- A lost acknowledgement is retried idempotently; the retry produced one cloud row, not two.
- Conflicts retain both local and cloud snapshots and require an explicit choice where no safe merge exists.
- Append-only message identity and additive Cosmos rooms are the only automatic merges.
- The production build still boots and operates with all non-local HTTP blocked; Supabase attempts without configuration remain zero.
- Two independent Chromium contexts detected and resolved a real shared-record conflict through a local conditional fixture backend.

What is not complete:

- No authorized Supabase test project, account or credential was available. Real cloud upload, download, reconnect, conflict, session expiry and cross-device delivery are **BLOCKED**, not simulated into a pass.
- Physical two-device testing was not possible; the browser evidence is explicitly a two-context simulation.
- Neural Map has no persistent index in the inspected code; it remains derived.
- Agents, proactive questions, UI state, improvements, memories and development identity records remain on their existing sync paths and were not converted to conditional continuity in this mission.

## 5. Revision contract

Metadata is keyed by `(authority, record id)`:

```text
localRevision, lastSyncedRevision, lastSyncedHash, hash,
cloudRevision, state, updatedAt, lastAttemptAt, lastError
```

Content hashes ignore transport-only fields (`updatedAt`, `createdAt`, graph `revision`, message ordering timestamps, visit counters). A timestamp touch is not a new revision; a content change is.

States:

```text
local_only | pending_upload | uploading | synced | pending_download
conflict | retry_required | authentication_required | cloud_unavailable
```

Rules enforced:

- local writes succeed before continuity runs;
- an acknowledgement applies only to its exact local revision;
- older acknowledgements remove only the older operation;
- a newer local revision supersedes an older queued operation;
- failed uploads preserve their payload;
- stale revisions are never uploaded over a newer local revision;
- records without metadata are adopted on first observation with a pending operation;
- cloud revisions come from the observed `updated_at` or document row revision.

Full contract: [`M14.4-WP02-REVISION-CONTRACT.md`](M14.4-WP02-REVISION-CONTRACT.md).

## 6. Outbox implementation

The outbox is part of `ContinuityStore` in the existing `KvStore`, not a second database. It stores stable operation ids and idempotency keys (`authority:recordId:rN`), the payload, expected cloud revision, attempt count, state, last error and bounded backoff.

Verified behavior:

| Case | Result |
|---|---|
| Offline write | local record persisted; pending operation created |
| Reload | outbox survives; pending count preserved |
| Authentication loss | payload retained; state `authentication_required` |
| Cloud unavailable | payload retained; batch stops; no tight loop |
| Interrupted upload / lost ack | retry keeps one cloud row |
| Duplicate delivery | idempotency key returns previous revision |
| Stale ack | revision 2 remains pending; not marked synced |
| Batch bound | 20 operations per pass; 1s–60s backoff |
| Storage bound | 2,000 operations; 200 conflicts |

Evidence: [`outbox-tests.json`](../../../artifacts/m144/outbox-tests.json). Full detail: [`M14.4-WP03-OUTBOX-RETRY.md`](M14.4-WP03-OUTBOX-RETRY.md).

## 7. Conflict policies

| Authority | Detection | Automatic merge | Resolution |
|---|---|---|---|
| Projects | both sides changed since base; conditional push | none | keep_local / keep_cloud |
| Conversations | conversation revision + message identity | union messages by stable id; later metadata | merge available |
| Knowledge library | both sides changed | none | keep_local / keep_cloud |
| KnowledgeGraph | whole-envelope hash/revision | none | keep_local / keep_cloud |
| SpatialObjects | same stable object id, different transform | none | keep_local / keep_cloud |
| Cosmos rooms | room-set revision | additive union by room id | merge available |
| Identity/security records | existing newer-wins path | not by continuity | retained, explicitly out of scope |

Every conflict retains local revision, cloud revision, local snapshot, cloud snapshot, authority, record id, reason and resolved state. A conflict changes the existing `PersistenceStateStore` status to **Conflict** and is never counted as synchronized.

The model-facing `continuity.status` and `continuity.resolve` tools use the same records through the existing dispatcher. No separate UI subsystem was introduced.

Full detail: [`M14.4-WP04-CONFLICT-RESOLUTION.md`](M14.4-WP04-CONFLICT-RESOLUTION.md).

## 8. KnowledgeGraph and Neural Map findings

**KnowledgeGraph**

- Remains the local authority at `lelu.cognition.knowledge.v1`.
- Preserves node id and edge key identity, envelope revision, `provenance: local`.
- Is **not** mapped to `knowledge_items`; the schemas and writers are different.
- Uses `user_preferences` document `lelu_sync_knowledge_graph` with a conditional row revision.
- Applying the same envelope repeatedly does not duplicate nodes or edges; live graph instances now receive the reconciled envelope.

**Neural Map**

- No standalone persistent Neural Map store/index was found.
- It remains derived from the canonical authorities.
- No new index, graph database or sync authority was introduced.
- Its refresh is therefore not a synchronization boundary; this is an explicit scope limitation, not a claimed persistent index.

## 9. Cosmos and spatial continuity

- `SpatialObjects` placements are synchronized per stable object id.
- Offline creation and transform changes persist and queue.
- The same record link cannot create a second placement.
- Concurrent transforms of the same object become a visible conflict; resolution uploads the chosen transform conditionally.
- `CosmosNavigation` persists only user/LÉLU rooms; system destinations are rebuilt by the runtime.
- Room deletion is archival, and the archived flag travels in the document.
- Room merge is additive; a missing room in one snapshot is not treated as deletion.
- `SpatialSceneGraph` is in-memory and excluded.
- Forge placements are server-owned and excluded.
- Camera/transient UI state is not synchronized.

Full detail: [`M14.4-WP06-SPATIAL-CONTINUITY.md`](M14.4-WP06-SPATIAL-CONTINUITY.md).

## 12. Security and authorization

- No credentials were added to source, fixtures, logs, reports or artifacts.
- Continuity uses `SupabasePersistence.continuitySession()`; it creates no client, token or service-role path.
- Without a connected session, the transport reports `authentication_required` and performs no upload.
- The Mission 14.3 dispatcher harness still refuses `project.apply` without authenticated authorization.
- A stale revision is rejected by the conditional transport; a stale acknowledgement cannot mark a newer revision synchronized.
- Unsafe conflicts remain unresolved until an explicit choice; no destructive auto-resolution.
- Continuity applies records through authorities; no tool dispatcher path is called by a cloud record.
- Partial synchronization cannot report a global synchronized state; per-authority status exposes pending, conflicts and failures.

Full detail: [`M14.4-WP09-REGRESSION-PERFORMANCE-SECURITY.md`](M14.4-WP09-REGRESSION-PERFORMANCE-SECURITY.md).

## 18. Known limitations

1. `updated_at` is a timestamp, not a strict per-write sequence; two writes in the same millisecond could be indistinguishable.
2. Document-backed authorities (graph, spatial objects, Cosmos rooms) are conditional at document-row level; one record conflict blocks the whole document upload until resolved.
3. Physical two-device testing was not performed; the browser result is a two-context simulation.
4. Neural Map has no persistent index; derived refresh is outside the continuity engine.
5. Agents, proactive questions, UI state, improvements, memories and development identity records keep their existing sync behavior and were not converted to conditional continuity in this mission.
6. Forge placements and `SpatialSceneGraph` are intentionally excluded.
7. A remote record is never treated as deleted merely because it is absent from a pull.
